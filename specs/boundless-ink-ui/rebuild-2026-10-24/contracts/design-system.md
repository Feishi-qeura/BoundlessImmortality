# newUI r1 · 四组统一设计输入

本轮按 quickstart 的新授权重做全部外观，包括 Main/HUD/Character/Inventory。旧 PRD 的“保留四页”、旧布局与旧 WBP 外观默认路径均不继承；保留的是业务规则、真实数据/动作、角色场景和可回滚证据。视觉未获用户批准，所有试作保持 approved:false，已授权连续制作无需再设流程批准门禁。

`style-contract.yaml` 是唯一令牌来源；本文只解释如何消费，不复制另一套色值。候选中的金边、墨绿、纸纹、山水可提炼复用，不能把候选的示例奖励、全页底图、虚构聊天/导航或服务占位符当实际功能。13张本轮指定候选已实际查看；来源与测量登记到 source-registry.json。

## 页面框架

720×1280 为逻辑设计画布，设备 SafeZone 后再内缩24。标准页的安全内容为672×1232。页头96、间距16、可选分类栏80、间距16、中段独立滚动、间距16、底部动作区112。带底部导航时导航占该底部区，不再叠加第二块112把内容挤小。设计图坐标按实际像素到逻辑画布的统一换算读取，不能把941×1672谎报为720×1280。

- 标准单列：页头 y24..120；分类 y136..216；正文 y232..1128；底部 y1144..1256。无分类时正文上移96，不留空条。
- 横屏1280×720：页头与操作区固定，中段重排为目录/列表 + 详情两栏；地图主视口加右侧详情；背包网格 + 属性详情；排行保持身份/指标列，不整体缩放竖图。
- 主菜单：标题、真实角色场景、主次操作三层分离。参考v3的主次按钮层级与空白，但取消空白大框强占角色场景；开始/继续/存档/设置/退出仍是真实动作。
- HUD：身份与状态放边缘，有限活动入口放上侧，底部5个主操作为角色/背包/修炼/排行/仙途。修炼映射真实 ToggleCultivation；暂停菜单仍提供存档/设置/返回主菜单。中央 x=.22W..78W、y=.24H..80H 为默认保护带，受真实角色投影动态校验，不复制旧HUD图标包作为新版完成。
- 角色：真实属性摘要 + 角色/修炼展示 + 装备/功法入口，数值排成可扫描列；换为新组件树，不能保留旧主体再加纸框。
- 背包：筛选/搜索/容量、稳定身份网格、同页或抽屉详情、明确动作区。竖屏5列起步，单元104×120加12间距；小宽度降列数而非缩字。装备/预留/过期/新增状态使用真字段，保留搜索与选择。

## 可复用页面族

1. 场景入口：main/home/character。真实场景或角色不能烘焙进整页图；新场景边饰只作独立透明层。
2. 列表与详情：inventory/saves/settings/经济/成员/功法。纸面承字、模块留白、固定动作；复用状态条、数据行、确认层。
3. 山水地图：world/resources/journey/region。地图等比裁切到视口，节点与文字独立；缩放只作用地图，不缩放按钮和文字；下方或右侧详情连续保留选中id。
4. 周期日历：sign-in/monthly/daily-verse。统一页头/标签/七列；同一面板只显示一个账户状态，不把参考中的“未领取/已领取示例”并列作为当前状态。
5. 榜单：leaderboard三类别共用完整模板，身份+名次+真实指标+来源范围；自排名未知不写“未上榜”；名次不由显示顺序推算。
6. 事件与结算：activities/launch/world-result/race-result/tribulation。hero可改变气氛，但状态只能一次呈现，成功/失败/对账互斥；奖励只来自匹配事件的权威receipt。

## 文字和状态

大字标题用马善政；正文/数值/按钮用霞鹜文楷，缺字有明确 Noto 回退。数据、日期、奖励和动作名始终为动态 TextBlock。至少在540×960与1280×720检查长名字、两位排名、极大数量、未知值和焦点。外部款式案例仅在需要新增研究时由各队查官方/商店来源；本轮已指定候选是授权加工输入，不引用其它旧本地图替代它们。

Unknown、Loading、Empty、Offline、Error、Pending、Disabled、Data 分开。未知数字是null/未提供，实际0是可显示的0；离线可标识旧快照但不能假装在线。不存在 readiness、normalized Q、预测/来源字段只影响这些展示槽，不阻止服务本来支持的合法请求。动作仍保留角色权限、连接、忙碌、版本、库存、确认、服务日期与原始执行规则。

## 四组最小合并片

- Player-A：main/home + 新根入口；Player-B：character/inventory；后续每片2~3页覆盖存档设置、装备功法外观、炼制来源、突破天劫。
- Rank-A：三榜模板及全部三类别数据状态；Rank-B：武灵总览+成员管理；Rank-C：建设/个人剑灵/礼物说明。
- Journey-A：世界/资源地图；Journey-B：日/月签到+每日一签；后续资源详情、竞采/历练结果与租约。独立UUserWidget必须通过owner架构的page宿主接路由/返回栈。
- Activities-A：总览/日常/限时；Activities-B：开服+任务/贡献榜；后续详情、离线和商店/寄售/订单。只读预算/价格缺失不能创造购买动作。

每片必须给出组件树与实际页面控件。几张PNG、一个纸底、一个slot或旧类中的局部挂件只能标 partial_component，不能把整页标为可见新版。每页的独立阶段与44行总表见 screen-contract.yaml 和 coverage-matrix.csv。

## 宿主/API边界

生产根/Base/Nav/Theme由 logic-integration 单writer维护，已读取 `../architecture-and-interfaces.md` 与 `../asset-root-contract.md` 并以其为准：新 Root 为 `UInkRebuildFrontendWidget : UInkFrontendWidget`，独立新树，默认包 `/Game/newUI/Runtime/WBP_NewUIFrontend`。独立 UUserWidget 组合由 host 包装并通过 UPROPERTY 保活，初始化阶段建树，嵌套动作显式收集。本文 PageKey/VM是业务数据契约，不新发明C++宿主函数或强迫继承旧可见布局。尚未发布的 presentation hook 函数名不自行假定；具体 Configure 签名由 owner 适配。页包可采用 Runtime/Pages 分组，公共字体/控件用 Shared，业务组件用 Components/<team>，不与迁移层级 Ink 重名。架构已对齐不代表类已编译或入口已接通。

所有新运行资源仅 `/Game/newUI`。旧候选PNG可作为来源证据；任何 `/Game/UI` 字符串只存在于明确兼容/迁移审计输入，不得写入新运行组件的默认加载路径。目录迁移与新版外观分别验收，由cleanup/integration执行，契约本身不证明迁移或删除完成。
