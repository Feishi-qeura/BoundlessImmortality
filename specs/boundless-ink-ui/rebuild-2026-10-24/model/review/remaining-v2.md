## Dispatch first

**N01 / P1 / Activities: do not require an existing event ID to start an absent event.** In `panel-activities/review-v2/staged-source/RebuildActivityWidgets.cpp:512`, the new guard rejects `ViewModel.EventId.IsNone()`. The real service requires the event to be absent and creates its ID inside StartLaunchEvent: `Tools/CultivationService/launch_event.py:114-122`. The native adapter also requires `bLaunchKnownAbsent`, not an existing event ID (`Source/BoundlessImmortality/Frontend/UiRollout20261024/LogicJourney/InkJourneyAdapter.cpp:150-161`). Thus a legal first start with `bCanStart=true` and an honest empty EventId is swallowed. Do not invent a fake future event ID. Capture a start subject such as anchor/guild/rules/profile plus a known-absent state; invalidate confirmation when that subject or day changes, and let fresh host Capture/Evaluate enforce native start rules. Day may be a confirmation fingerprint, but do not make an unrelated missing display field a new service precondition. The former empty-day request issue is fixed in lines 529-533; this new EventId gate remains open.

**N02 / P2 / Journey: monthly confirmation crosses a service-day/month change.** `panel-journey/review-v2/staged-source/Frontend/UIRebuild20261024/Journey/InkJourneyNewWidgets.cpp:161` replaces ExpectedServiceDay/ServerMonth/Milestones without resetting/capturing the open confirmation. Line 167 broadcasts the *new* ExpectedServiceDay with the old selected milestone on second click. A fresh host day comparison will pass because the UI substituted the current day. Capture `(service day, month, milestone)` at the first click; retain on same-subject refresh, invalidate on day/month/milestone identity change, and emit the captured subject. This is a presentation confirmation defect, not evidence of duplicate server rewards.

**N03 / P2 / Integration + Player: visible item identity is not captured by the click action.** Production `Source/BoundlessImmortality/Frontend/UIRebuild20261024/Player/InkPlayerCharacterInventoryWidgets.cpp:344-348` gives the widget an EntryId name but sends `InventorySelect_<SlotIndex>`. `Frontend/InkInventoryWidget.cpp:503-506` resolves that slot against the current model. If an authority projection reorders/replaces slots before the next UI refresh, a click on the old visible item selects another item. Detail and mutation paths correctly use the selected EntryId afterward, but that does not repair the initial selection mismatch. Add a GUID-bearing selection intent and resolve/validate the exact EntryId at click time; keep physical empty-slot intents separate. Do not remove the existing fresh authority checks in InventoryAction.

**N04 / P2 / Integration + Journey: actual font mapping differs.** Theme loads `/Game/newUI/Ink/Fonts/Shared/F_InkBody` and Display; the cleanup map explicitly maps those canonical targets (`migration/migration-map.csv:11-12`). Use the mapped paths or shared font helper/injection and verify imported packages later. Cleanup owns migration; this review requests no migration edit. A fallback font is not proof of delivered typography.

**N06 / P2 / Integration: cached inventory content omits action eligibility inputs.** Root `.cpp:186-187` keys on selection/filter/search/page/quantity/capacity and each entry's id/name/description/slot/count/equipped/new flag. The view's action enabled state also depends on Category, bUsable and bSellable (Player builder 426-434), and authority/local projection state can change. A same-count metadata change can leave an action visibly disabled until an unrelated key changes, despite fresh host authorization permitting it. Include all rendered/action inputs or an authoritative projection revision in the content key; avoid deriving eligibility from display completeness. **N07 / P2 / Rank: failed avatar completion cannot release the new in-flight latch.** Review-v2 `InkRankWulingPages.cpp:152-156` returns for a null Avatar before removing ParticipantId from AvatarRequestsInFlight. On a failed async download, the natural completion with nullptr leaves the avatar permanently pending in this page instance. Remove the in-flight key on both success and failure and expose a failure/retry path with host backoff; preserve participant-keyed cache/image lookup for success. This is an uncovered source failure path, not an observed network run.

**N08 / build-risk / Rank: complete UFont type in the new base translation unit.** `InkRankWulingPageBase.cpp` converts a forward-declared `const UFont*` into FSlateFontInfo's `const UObject*` parameter, but neither this file nor its own header includes `Engine/Font.h`. **N09 / P2 / Rank: tab text resolver returns the wrapper's button instead of its label.** `InkRankWulingPages.cpp:121-125` obtains the button's parent USizeBox and casts `HitTarget->GetContent()` to UTextBlock. This is a source resolver defect; screenshots/contrast acceptance remain unrun.
