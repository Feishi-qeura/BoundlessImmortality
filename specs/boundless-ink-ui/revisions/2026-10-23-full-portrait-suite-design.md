# 全量竖屏修仙 UI 套件扩展设计

- 状态：待用户审阅（设计草案，不是页面或资产批准）
- 日期：2026-10-23
- 项目：BoundlessImmortality / `specs/boundless-ink-ui`
- 目标：为现有 UI 设计项目扩充完整竖屏套件规格，并为后续页面原型、组件资产及 Unreal Engine 接线提供同一份可执行基线。

## 意图

将已有水墨修仙 UI 项目扩充为面向竖屏手机的完整产品套件，支持单手进入修炼与地图、角色成长、背包管理、武灵协作、排行、签到和活动。后续开发者应能按页面契约和状态数据实现界面，不需从自然语言重新推断功能。

用户明确范围包括：主菜单、主页面 HUD、角色属性、角色背包、伤害/修炼速度/主播剑灵排行榜、武灵、世界地图、资源地图、每日吉凶签、月签到、日常/限定/常驻/开服活动，以及开服贡献榜、每日任务、特惠购买入口；并给出从筑基至混元无极的突破材料、品质、倍率、材料来源、准备度和飞升渡劫设计。

## 已核对的项目现状

项目已存在已批准的 UI 文档、路由和交互契约、既有水墨字体与色彩规范、主播/剑灵/武灵身份约束，以及主菜单、HUD、角色主面板、背包等保留边界。既有策划规定主播、观众剑灵、武灵集体成长分别展示；武灵是主播创建的组织，不是召唤宠物。主播突破的品质与天劫概率分开；免费世界历练与稳定材料来源必须保留。

因此本设计是扩展和整理现有契约的增量，不另建重复路由，不覆盖保留页面或场景。当前主审尺寸沿用逻辑 720×1280（9:16），横屏 1280×720 为重排适配；项目仍为 UE5.8，设计产物以通用契约和素材交接为界，不声称自动生成 UMG 或 uasset。

## 设计方向与方案取舍

### 方案 A：全量重画成写实仙侠 MMO

优点是贴近 3D 角色与场景游戏；缺点是与现有水墨规范、已批准 HUD 组件和保留页面不一致，重制成本高，视觉验收会和现有基线冲突。

### 方案 B：全量水墨页面

优点是系统统一且接入现有资产较直接；缺点是活动、材料品质、排行榜和组织数据密集，所有内容使用重纸纹与高装饰层容易降低信息辨识和可读性。

### 方案 C：水墨框架 + 真实场景与轻量 HUD + 信息页强化层级（选定方向）

沿用现有水墨契约作为标题、卡片边界、按钮与图标语言；主场景和 3D 角色保持游戏运行画面；战斗 HUD 采用轻量半透明控件，属性、背包、榜单、活动、签到和突破页使用清楚的纸墨面板。重要品质色仅作辅助标记，不能替代文字。此方向已由用户确认。

## 页面与导航范围

沿用当前 `screen-map.md` 中稳定页面 ID 与路由，按以下产品分区组织，不新增重复顶层页面：

1. **主流程**：主菜单 → HUD → 仙途入口 → 世界地图/区域/资源地图；HUD 可进入角色、背包、排行、活动、签到。
2. **成长**：角色属性 → 装备/功法 → 突破准备 → 材料来源；金丹六阶至元婴及后续可用时进入渡劫事件。
3. **社交组织**：武灵总览 → 成员/贡献/建设/记录；观众的个人剑灵页单独呈现，榜单明确榜单主体。
4. **签到活动**：每日一签（大吉、吉、平、凶）与奖励结果、月签到、日常、限定、常驻、开服活动；开服活动可在 HUD 显示精简倒计时与下一任务提示，点击进入活动详情。
5. **榜单**：伤害、修炼速度、主播剑灵三个独立分类；每项必须显示统计周期、单位、当前账号位置、更新时间和无数据/未上榜状态。若“主播剑灵”排行主体或计分维度与现有服务字段不一致，UI 使用经确认的服务字段，不自行合成总战力。

完整路由列表、当前功能开关和已定页面处理方式以现有 `screen-map.md` 与 `screen-contract.yaml` 为基础，本设计要求逐项补齐视觉与状态契约。

## 核心布局约束

### 主菜单与主页面 HUD

- 主菜单负责开始/继续、存档选择、设置和返回；按钮触控区不小于 44 dp，重要主操作放在拇指易触区域。
- HUD 顶部显示头像/身份、修为与境界、血量及必要状态；右上快捷入口承担活动、签到、仙途与限时开服提示。
- 中央场景保护区优先留给真实游戏场景和角色。活动提示只显示短标题、剩余时间和可领取/待办状态，不铺满角色。
- 底部导航沿用当前已批准入口结构，角色、背包、修炼/仙途、排行、菜单；不额外堆叠第二排入口。
- 开服倒计时在活动有效期内出现，过期后由活动配置移除；入口不可依据本机日期自行生成状态。

### 角色属性与背包

- 角色页沿用现有丹田/属性、装备与评级结构，展示真实数据；新增突破进度和入口时不重排或覆盖现有主面板。
- 背包保留已定义容量、搜索、分类、格子、多选、分页和底部操作。材料格显示名称、品质、数量、绑定/来源标记；容量不足、无筛选结果和材料缺口均有明确状态。
- 点击突破材料可查看作用、当前数量、获得方式及适用境界；“前往获取”必须连接到真实开放来源。

### 武灵、世界地图与资源地图

- 武灵页以组织概况、主播身份、成员数、贡献、集体进度和建设入口为主；成员状态与主播个人境界分列。不得使用宠物召唤、宗门加入等误导视觉隐喻。
- 世界地图展示区域、解锁条件、推荐境界、已发现资源/秘境和前往方式；资源地图区分可持续探索的免费路径、临时资源点及竞争状态。
- 地图标记使用状态图例与文字，不能只靠颜色；锁定区域明确写出条件或来源。

### 签到与活动

- 每日一签页面显示当日签运（大吉/吉/平/凶）、结果说明、奖励和领取/已领取状态。签运由服务提供；不在客户端随机重抽，也不暗示可付费改签。
- 月签到使用月历格、累计进度和实际可领状态；跨月、补签、连续天数以服务契约为准。
- 活动页采用日常、限定、常驻、开服分类；每条活动展示起止时间、进度、奖励和前往条件。开服页分出贡献榜、每日任务和特惠物品购买区域。
- “特惠物品购买”仅作获准商品和购买能力的承载位置。价格、库存、购买结果、支付确认由权威服务提供；没有可用/获准 SKU 时隐藏购买按钮或明确标记未开放，不构造价格与折扣。

## 突破界面和材料规则表达

突破页固定展示：当前境界 → 目标境界、核心资格材料、可选护道材料、天地精华、天材地宝、突破准备度、当前材料来源、品质评分、预计属性成长范围，以及开始突破按钮。材料槽位最多四类；早期只显示当前境界开放的类别，避免新手首屏出现十几种材料。

用户提供的品质表作为设计意图基线：Q 0–39 凡品 ×2.5；40–59 良品 ×3.0；60–74 上品 ×3.5；75–89 极品 ×4.0；90–97 天品 ×4.5；98–100 完美 ×5.0。只使用合格核心材料可完成突破，基础成长至少 ×2.5。界面需显示确定的预计结果或窄范围，不能把 ×2.5–×5.0 做成无提示盲抽。

界面继续将“突破品质/属性成长”和“天劫成功概率”分开展示。只有规则配置要求时才显示天劫阶段、准备选项与失败后果；天劫装备/助力不伪装为提升品质分的材料。大乘→飞升可显示肉身、神魂、心魔三阶段概览。世界唯一材料必须提示来源与稀有性，普通核心材料路径保持可见。

### 必须在开发执行前对齐的数值冲突

用户这次给出的概览说 Q 为四类材料评分之和、满分 100；材料品质示例又给出单个核心材料 10/18/26/35 分，另外护道、精华和奇珍也会增加评分。若不定义每类上限和归一化，合计可能超过 100；而“突破前 2.5–5 倍”也需明确是每项基础属性倍率还是总面板战力。

现有 v1.4 突破数据表和天劫契约是本项目开发数据依据。进入数值字段锁定前，开发者必须做一张逐境界表，核对 Q 上限、类别权重、材料评分、倍率插值/档位、准备度影响、失败消耗与天劫概率；不得同时把用户概览与旧数据当作两套并行公式。当前文档只冻结 UI 呈现字段与解释方式，不覆盖数值权威表。

## AI 开发契约与状态

每个页面需要登记：`screen_id`、入口/返回、职责、布局区域、控件 ID、数据来源/ViewModel 字段、可交互状态、加载/空/错误/锁定/已领取状态、权限/功能开关、事件名和可访问性标签。UI 不根据本地时间、模拟数字或展示用随机生成真实业务进度；测试预览数据须有明确的预览标记。

核心 ViewModel 至少覆盖：`AnchorVm`、`InventoryVm`、`LeaderboardVm`、`GuildVm`、`WorldVm`、`ActivityVm`、`LaunchVm`、`BreakthroughVm`、`TribulationVm`。路由按既有页面合同与已批准功能开关解析，未开放功能不能仅通过手工 URL/路由进入。

所有重要点击均有禁用原因或进行中状态；领取、突破、购买、建设等非幂等动作使用服务确认结果，不因界面重开重复发奖或重复扣费。返回操作恢复筛选、页码和滚动位置。

## 验收目标

- 所有指定页面/子状态在现有页面地图中有稳定入口和返回路径，且手机竖屏下可读、可点。
- 9:16 与横屏适配遵循同一信息层级；旋转不重复提交签到、购买或突破请求。
- 活动倒计时、签到结果、榜单周期与数值、突破材料和预期成长均来自权威字段。
- 主播、剑灵与武灵数据主体清楚区分；材料缺失时提供真实来源；未开放服务不显示伪造的成功状态。
- 水墨视觉一致，标题使用马善政体，其他文字和数字使用霞鹜文楷；血量文案沿用现行规范。
- 设计包结构校验仅验证契约文件；后续视觉候选还需逐页审阅，运行接线另需 Unreal 编译、PIE 与适用设备验证。
