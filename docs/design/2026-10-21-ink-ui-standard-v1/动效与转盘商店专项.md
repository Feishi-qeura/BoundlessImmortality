# 动效、Niagara UI、转盘与商店专项

配合 [UI开发规范](UI开发规范.md) 使用。以下是建议实现约束与预算，尚未在本项目运行验证。用户欣赏 UI 动效，本案以“动作解释状态变化、关键时刻有演出”为原则，绝非给每张卡片永久发光。

## 1 动效的分工

| 系统 | 适合负责 | 不应负责 |
|---|---|---|
| UMG Animation / 原生时间轴 | 进入退出、位移、缩放、透明度、按钮反馈、转盘角度、结果布局 | 权威扣币、最终奖励、伪造进度 |
| UI 材质 | 墨迹显隐、云气缓流、金边扫光、条轨流动、软边融合 | 更新玩家资产或隐藏所有交互边界 |
| Niagara UI | 灵气轨迹、少量纸屑/花瓣、奖励爆发、飞入目标的粒子 | 每一条正文背景、转盘随机算法、商品的唯一可见状态 |
| 音频/可选触觉 | 按钮确认、落点、获得、失败 | 替代视觉说明或无法关闭的持续噪声 |

静态骨架先保持清晰，运动负责“聚气→触发→到达→收束”。推荐节奏：操作反馈立即开始，页面 0.24–0.32 秒稳定，奖励主要阅读结果在 1 秒内出现，长转盘演出可跳过。网络等待独立显示，不伪造精确处理百分比。

## 2 时序表（秒，候选值）

| 场景 | 时序与运动 | 材质/粒子 | 退出/打断 |
|---|---|---|---|
| 普通页打开 | 0–.08 纸底Opacity0→1；.04–.28 标题Y+12→0；内容按.025错峰、总错峰≤.12 | 山脚mask在.08–.32展开；最多一次小云气 | 可反向退出；连续开关从当前表现值接续 |
| 普通页关闭 | .18，内容先淡、纸壳后淡；不能锁输入直到动画结束 | 停新发射，残留≤.25清完 | 提交事务不随动画撤回 |
| 按钮触发 | pressed .07，视觉缩放1→.97；release .10回1 | 可用主操作一次.24边缘扫光 | 控件Disabled时不能触发 |
| 标签切换 | .16，旧内容淡出.06，新内容+8→0 | 选中金线滑动；不用全屏墨爆 | 快速切换取消旧视觉回调 |
| HUD修炼待机 | 2.8–3.6呼吸，亮度变化≤12%，不缩放文字 | 中心一条慢轨迹；不是五图标都闪 | 隐藏/收功即停，ReducedMotion用静态高亮 |
| 入定成功 | .0-.18按钮收束，.18-.55灵气汇聚，.55-.9稳定 | 轨迹向中心收，单次波纹；由真实状态事件触发 | 失败回原态并显示原因 |
| 收功/中断 | .25-.4收束，动作名及时改变 | 停循环，向外淡去；不再自动启动 | 不等动画结束才释放业务状态 |
| 真实数值变化 | .18-.3插值展示，最终值始终可查 | 进度头一个亮点；受伤缓冲轨道独立 | 归零/销毁时取消插值回调 |
| 道具选中 | .12金边显现，插画不跳格 | 单次沿边走光，不常驻粒子 | 换项清上一项效果 |
| 奖励弹出 | .0-.12底色，.12-.4道具到位，.4以后可继续 | 稀有物一次.4-.8爆发，普通物仅墨点 | 跳过只跳表现，保留收据 |
| 获得飞入背包 | .25停留后.45弧线飞行，目标点短闪.12 | 1个汇聚轨迹，多物品合并最多3条 | 目标不可见改Toast；不飞到屏外错误坐标 |
| 列表新数据 | .12-.18淡入，可见行错峰总≤.12 | 无常驻粒子 | 滚动不重复播放全部出现动画 |
| 失败 | .08轻色变+.18恢复，原因停留可读 | 不做全屏红闪/大幅抖动 | 保留输入、数量与当前项 |

所有状态的 Hover 与 Pressed 是短反馈；Pending、Selected、Available 不是同一效果。数字动画与粒子都订阅同一结果事件，但不反过来驱动结果提交。

`ReducedMotion` 模式：位移/呼吸/持续旋转关闭，页面仅 .10–.15 淡入；结果直接展示，转盘≤.3过渡；粒子关闭或改静态高亮。提供 UI 动效强度、跳过已见演出、UI音量设置，设置只影响表现。不能关粒子后让按钮完全不可辨识。

## 3 Niagara UI Renderer 的正确边界

### 3.1 两种同名实现要先认清

| 分支 | 已查资料 | 本案约束 |
|---|---|---|
| 第三方 SourySK/NiagaraUIRenderer | 原仓库说明支持CPU sprite/ribbon、UI域材质、Material Remap List | 可按原仓库做UI材质映射；不能假定其版本已支持本项目UE5.8/全部目标平台 |
| UE5.8文档列出的引擎插件 | Epic列出 `Engine/Plugins/FX/NiagaraUIRenderer`、CPU专用UI sprite renderer，标注Experimental | 依实际引擎插件/API验证，不能把第三方的widget字段、ribbon能力直接当内置接口 |

来源：[第三方原仓库](https://github.com/SourySK/NiagaraUIRenderer)、[Epic UE5.8插件说明](https://dev.epicgames.com/documentation/unreal-engine/API/PluginIndex/NiagaraUIRenderer)。本轮 `.uproject` 中没有显式启用该插件，项目 `Plugins` 目录没有此插件；未穷尽检查引擎安装目录，因此不能断言整机未安装。**接入时先锁定来源、版本、目标平台和实际类名；两套同名插件不要同时装入。**

### 3.2 第三方分支的推荐接法

先做一个独立演示控件证明：CPU emitter、sprite、UI材质、颜色/Alpha、裁切/缩放、可见性与销毁。ribbon 另测后再用于轨迹；不把GPU、Mesh、世界深度碰撞作为UI粒子能力前提。原世界系统只复制/派生，不改其材质破坏世界显示。

UI材质使用 `Material Domain=User Interface`，颜色用 Vertex Color；不假设所有 Particle Color/Radius/Random 世界节点可用。第三方原仓库说明 sprite 的 Dynamic Parameter R/G 可从 TexCoord1 取，其他通道/renderer需按实际版本测。用 Widget Material Remap List 将世界材质映射为UI版本；该列表是第三方机制，内置分支应读实际API。

UI不自动获得世界后处理Bloom。柔光用纹理、叠层和正确的透明混合实现，不靠极高发光数值烧白纸底。白/灰/黑背景、页面缩放和高对比模式均测Alpha；若出现黑边先核对直通/预乘混合而不是增加亮度掩盖。

### 3.3 生命周期合同

每个页面FXHost独占所属效果，绑定页面状态，不靠全局Tick不断Activate。

```text
页面进入可见状态 → 验证系统/材质/宿主就绪 → 设置参数 → Activate一次
Pending→Success → 收到同一RequestId的成功事件 → 播放一次性结果FX
页面失焦/被覆盖/隐藏 → 停循环、停新发射、取消定时器/延迟回调
页面关闭 → Deactivate → 有上限的残留收束 → 必要时DeactivateImmediate → 归还/销毁
宿主销毁/关卡切换 → 解除委托、清池、清回调；后续异步结果仅写VM
页面重新打开 → 读取VM快照；不重放已消费的奖励FX，不重复业务请求
```

具体函数及调用顺序应对照实际组件类型；本案沿用项目已有Niagara清理经验，要求先停止正常发射再做强制清理。只设Collapsed不能证明不再模拟。异步加载/PSO延迟期间保存一次待播放请求，在宿主仍可见且RequestId未消费时播放；关闭后不得突然补播。记录重复Activate、残留模拟和延迟就绪的测试结果。

流动/循环粒子位于独立非命中层，页面FX层在正文下方或文本保护区域外。Retainer/Invalidation、ScrollBox裁切、DPI缩放、窗口旋转必须对实际插件回归。跟踪“系统数量”与“活粒子数量”，不能只按发射率估算峰值。

### 3.4 质量档与性能目标

以下为初始设计上限，**不是已达到性能**：

| 档位 | 同时运行UI系统 | 活粒子总上限 | 短爆发上限 | 处理 |
|---|---:|---:|---:|---|
| Low | 1 | 60 | 100 | 关闭装饰循环/ribbon；主反馈材质替代 |
| Standard | 3 | 180 | 260 | 仅当前主焦点+1个结果+1个过渡 |
| High | 4 | 360 | 480 | 只增精度/轨迹密度，不加更多抢焦点闪光 |
| ReducedMotion | 0 | 0 | 0 | 静态高亮与短淡入 |

短爆发仍计入全局活粒子预算，只允许在短时峰值上限内；同页面多次奖励合并或排队，不能每格各开NS。所有高亮覆盖面积要受限，尤其是半屏透明云气造成的过绘。与世界Niagara分开统计。

候选验收目标：目标设备60fps档预算16.67ms/帧，30fps档33.33ms/帧；完整UI相对同场景无UI的CPU增量p95≤1.5ms、GPU增量p95≤1.0ms。低端达不到先降粒子和过绘，再降低不重要层更新率。必须固定相机场景/分辨率/质量，暖机后连续采样≥60秒，注明机型、温度和刷新率；没有实测不能把这些目标写成结果。

## 4 抽奖转盘：构图、状态、落点与恢复

### 4.1 页面结构与尺寸

以“仙缘寻宝”作为视觉候选标题，正式名称由产品决定。一个页面一个视觉中心：固定指针、独立轮盘、独立奖励图标/文字、中心章、外环和结果层。

P竖屏（720×1280，无额外安全区）：页头88；规则/奖池详情入口与货币条64；轮盘区高度560、直径 `min(W-96,560)`；奖励摘要96；单次/十次按钮区104；跳过/记录88。所有布局含24模块间距时由内容区实际求和，超过可用高度则奖池预览滚动，CTA和规则入口固定；不能把轮盘缩到看不清或盖住按钮。正式盘面建议8格，扇区数从版本化奖池布局配置读取。

长竖屏多出的高度给盘面周围山水和奖池说明，直径不无限放大。方屏：盘面左/上、动作右/下，保证奖品热点；L横屏：盘面占左侧约56%，右侧奖池预览/成本/按钮/记录44%，整体宽≤1180。轮盘始终圆形。视觉图标48–64，点击说明热点≥88；盘面过密时点击“奖池详情”打开清楚的大列表。

主界面必须看见：奖池/规则、抽取成本与持有量、单次与批量动作、跳过动画选项、记录；存在保底/限购/有效期时按真实规则显示，缺少则不添加假数值。盘面等角度仅是布局，不表示各奖品等概率；概率若存在，来自权威配置并可查看。所有价格、抽取次数和示意图内容不能从概念图OCR生成业务配置。

### 4.2 分层与图标方向

```text
软边背景/山水
  外圈云纹（慢流，可关闭）
  WheelRotatingRoot：盘底 + 扇区 + 奖品中心位置
    ItemIcon/Label：保持正向，必要时反向抵消父旋转
  FixedPointer：12点方向，独立于旋转根
  CenterSeal：默认固定，不能覆盖奖品或规则
  SectorHighlight：停稳后按真实结果高亮
  ForegroundCloudFX：不遮指针/图标/操作
  ResultModal：独立层级
```

如果奖品图随盘旋转会更真实，文字仍必须在停稳后正向易读；快速旋转期间可以只显示图标，停稳再显示文字，不能让细字旋转产生噪声。装饰云气可遮外轮廓，但不能改变扇区中心位置或藏住指针。

### 4.3 状态机与事务

| 状态 | 界面 | 允许操作 |
|---|---|---|
| Loading | 占位/请求态，无假奖池 | 返回、重试 |
| Ready | 当前配置、余额、成本 | 查看详情、发起 |
| Confirming | 完整成本、次数、当前余额 | 确认或取消；免费路径可按产品规则省略确认 |
| Requesting | 提交唯一request_id，禁用再次提交 | 返回；不能以UI超时认定没扣币 |
| ResultCommitted | 已有权威receipt/result列表和新快照 | 开始/跳过表现 |
| Presenting | 按结果播转盘 | 跳过、返回；禁止再次提交同笔 |
| Revealed | 奖励与收据，余额已对账 | 确认、下一次（新request_id） |
| Reconciling | 超时/断线/恢复，查询原请求 | 返回、查询；不重随机 |
| Error/Expired/Disabled | 明确原因和下一步 | 允许安全重试/离开，不能假成功 |

UI模型建议包含 PoolId/PoolVersion、布局SectorId、ItemId、Cost、Count、BalanceSnapshot、RequestId、ReceiptId、Results、ServerTime、PresentationConsumed。正式服务必须验证奖池版本/余额/开放条件并返回结果，客户端的角度只用于演出。

**正式操作顺序：确认成本→唯一请求→服务端结算并返回结果/收据→更新数据快照→转盘演出→结果确认。** 可先做不带落点的聚气等待，不能在结果未到时随机停一个奖品再“修正”。超时查询同一request_id；幂等性应由服务保证，UI锁按钮不是事务幂等实现。

离页/切后台时停止表现，保留事务结果；回来显示未读收据或已确认结果。不因重播动画再发奖励，也不因跳过把奖励漏掉。旋转屏幕保留结果，只重算盘面位置；中断后允许直接结算展示，不必从当前角度无缝继续。

十次抽取：一次批量权威结果，按返回顺序展示1次代表性盘面演出，然后2×5奖励结果；不是客户端十次重随机。若产品要求逐次演出，必须由同一批results依次驱动且可一键跳到完整结果。重复奖励按真实数量汇总，保留逐次记录可查看。8格盘面无法表达全部奖池时使用版本化扇区映射/“其他奖励”语义，不能把真实奖励硬塞到错误图标扇区。

### 4.4 确定性角度公式

仅适用于N个等角扇区的默认实现。UI局部坐标Y向下，从12点顺时针角度增加；引擎RenderAngle符号需一次实测校准。扇区i覆盖 `[iΔ,(i+1)Δ)`，`Δ=360/N`；其中心 `c_i=(i+0.5)Δ`；固定指针 `p=0°`。所有角度以度计算。

```text
mod360(x) = ((x % 360) + 360) % 360
落点视觉偏移 ε ∈ [-0.15Δ, +0.15Δ]，来自一次保存的表现种子
target = mod360(p - c_i - ε)
final = start + 360*k + mod360(target - mod360(start))
u = clamp(t/T, 0, 1)
s(u) = 6*u^5 - 15*u^4 + 10*u^3
angle(t) = start + (final - start)*s(u)
停稳校验：floor(mod360(p - final)/Δ) == i
```

k建议4–6，Low可2–4；T建议3.6秒。此曲线从零速启动、加速后减速并零速结束；不用宣称它有固定巡航段。公式只选择同一奖品内部的视觉位置，**ε绝不能重新决定奖品**；非等角扇区用各自start/end角与中心，并在校验中按配置区间查找，不能套floor。

声音/小闪光在角度跨越扇区边界时触发，限频≤8次/秒，最后减速可逐格响应；不能每帧播放一次。旋转累计角使用未归一化值，绘制可取mod360，避免359→0插值反转。布局旋转/父变换只影响显示坐标，不更改i和收据。

### 4.5 演出节点

| 节点 | 时长 | 画面/声音 |
|---|---:|---|
| 聚气等待 | .25–.4起步，之后低强度等待 | 外环微亮，明确“请求中”，不无限大转盘 |
| 旋转 | 3.6 | 先加后减，轨迹集中外环，不扫过CTA |
| 定格 | .18–.25 | 指针对应扇区金线，短落点声；最终几何不再随机弹跳跨界 |
| 显奖 | .3–.5 | 普通墨点、稀有金青一次爆发，真实Item/数量 |
| 可继续 | 最迟显奖后.4 | 完整结果、确认或新请求；跳过直接到此 |

测试至少包含N=8所有扇区、start为0/359/720等、正负ε边界、长帧、跳过、离页、快速点击、批量、超时、重连、旋转屏幕、重复回包和旧版本奖池。**不是靠观看一次“转起来了”就通过。**

## 5 商店、寄售与订单

### 5.1 商店布局

商店参考图中的“云山坊市”是主题候选，不改正式Route/SKU。主标题+两种以内常用货币；更多货币折叠详情。默认分类推荐/材料/丹药/外观仅作视觉分组候选，实际SKU不支持的类别隐藏。寄售与NPC商店分别入口，不能把玩家税费混进NPC商品。

P：顶部标题88 + 货币/分类点击行至少88 + 精选横幅约144（可无） + 2列商品网格 + 底部选中摘要/购买区136。普通商品卡最小宽 `(W-48-16)/2`、高200–224；商品插画80–104，名称最多一至两行、价格单行，数量/库存标记独立。首屏建议4件清楚可读，再滚动看更多；横幅不得挤掉所有商品。没有精选数据就收起横幅，不放“敬请期待”占四分之一屏。

L：全页主体三栏，分类160 / 商品区约560 / 详情约360，栏间16；容器宽可至1180。商品区按可用宽每列至少176计算，常见3列；如果剩余宽不足，不硬塞3列，应降2列或移除精选横幅。详情含大图、完整说明、绑定/有效期/来源、价格、数量、限购、总价、购买CTA。C方屏采用2列网格+详情层，避免3栏缩字。

商品滚动而标题、分类、余额、当前购买区固定。切商品更新详情，不每张卡都放大“购买”按钮。选中金边、Hover蓝、售罄灰/文字、限购标签、倒计时位置固定；图标不能因物品长宽比例跳动，全部Fit于同一展示框。

### 5.2 购买信息与动作

购买前可见：商品名、产物数量、单价和币种、可买数量、个人剩余额度、必要绑定材料、实际总成本、是否到期/绑定、库存和背包限制。数量步进/输入的交互热点至少88；不允许负数/超限/溢出；总价用整数最小货币单位或服务端金额格式，不以浮点乘法显示相差1的成本。

真实折扣可显示原价和现价，虚构折扣/假倒计时不能补进概念图。无价格数据时显示“暂不可购买”，不能用0当免费。外观可预览但不扣币；试穿与正式购买有不同文字和状态。余额不足原因、返回获取入口可见，但不擅自发起平台送礼/支付。

```text
Ready → Selected → QuantityEditing → CostPreview → Confirming
  → Pending(RequestId, SkuVersion, Quantity, ExpectedCost)
  → Success(ReceiptId, InventorySnapshot, BalanceSnapshot) / Rejected / Reconciling
```

服务端成本/库存变化时重新展示差异并要求对新成本作真实确认，不能沿旧确认直接多扣。Pending只禁该笔提交，不锁返回；快速点击仅一个有效请求。超时显示确认中并查询，不立即出现重购大按钮。成功后以服务端新库存/余额更新；飞入背包只是表现，不在动画结束时再加道具。背包满、限购、材料不足、售罄、过期、断线均给明确理由。

### 5.3 寄售/订单的差异

寄售显示卖方提供的整单数量、单价、总价、手续费/税、到期、托管/绑定限制；整单买入或部分买入严格按现有业务能力。挂牌、撤单、成交、应收使用各自请求与收据，不和购买确认共用模糊“确定”。不把本地列表冒充跨玩家市场。

订单页包含处理中/成交/取消/到期/失败状态、时间、数量、完整总价、收据/订单标识和查询恢复。滚动回列表保留筛选与选中。旧规划限定原型经济profile时继续遵循配置与服务拒绝规则，界面隐藏入口不能代替服务端鉴权。

### 5.4 商店动效

打开：纸底.24淡入、主题山水.32显现；商品只对首屏可见项错峰，总延迟≤.12。选中：金边.12、主图轻微1→1.02仅一次；不要把商品变成不停浮动的粒子展示柜。购买：按钮立即反馈并进入Pending；成功后道具短闪+最多三条合并轨迹到背包，余额平稳更新；失败显示原因且保留选择/数量。精选外观允许一个独立慢预览，不扩散到全部商品。

## 6 专项交付证据

要求5–10秒实际渲染录像：打开/返回、修炼入定与收功、单次转盘/跳过/十次结果、商店成功/失败各一次；另需中断与销毁日志、结果一致性测试和真实设备性能报告。录像有声音、跳过设置和ReducedMotion对照更易审查。当前包仅提供规范与静态概念图，不把这些未来验收要求标成已通过。
